# oimimo scheduler — 项目说明书

> **版本**: v1.5.0 · **更新**: 2026-10-06
> **技术栈**: Python Flask 3 + SQLite (WAL) + HTMX 2 + Jinja2 + Pydantic v2 + Tkinter 启动器
> **v1.5.0 定位**：后端标准化版本——五类枚举存储值全面英文 code 化，**用户界面中文保持不变**。详见下文「版本与数据兼容」。

面向**独立插画师**的本地接单排单管理工具，覆盖完整工作流：

```
接单 → 排期 → 跟进 → 收款 → 统计 → 归档
```

**核心原则**：本地优先（SQLite 单文件，不上传数据）· 桌面集成（启动器+浏览器，类原生体验）· 动态可配置（注册表/主题/选择列表免改代码）· HTMX 无刷新 · 不 SaaS 化。米画师集成是用户主动开启的本地 Playwright 只读连接。

## 功能矩阵

### 主页仪表盘 `/`
- 统计卡 5 指标：进行中 / 本月到账(+环比，Spec 26 事件流口径：分期按到账日、整单按排期月) / 逾期 / 已完成 / 待收金额(= 应收净额 − 已到账)；点击弹**小票明细**（待收小票分期单按单列三数：应收/已到/待收；到账小票分期单按笔一行带「分期」标签）
- 可折叠时间范围：预设（本月/季度/年/全部）+ 自定义日期
- 甘特图（Frappe Gantt）：日/周/月/年 4 视图，拖拽改排期，今日居中定位
- 本周排单表 + 逾期提醒表

### 收入看板 `/income`
- Chart.js 图表：月度收入（按到账归属 · 净额）/ 每月预计(虚线，待收部分按排单月 · 净额) / 年累进 / 品类分布(毛净分列) / 客户排名 Top 8
- **时薪统计**：本月/历史平均时薪 + 近 12 月趋势折线 + 品类/来源条形图（全局开关控制，单订单可排除）
- **报价建议**：历史时薪 × 预估工时 ÷ (1−抽成)，附 P25~P75 区间
- **gridstack 自定义布局**：Notion 式拖拽+缩放+持久化
- 年份自动发现切换；近 3/6/12 月范围

### 日历视图 `/calendar`
- FullCalendar 6 月/周视图
- **5 种着色模式**（来源/阶段/DDL/收款/类别）独立调色 + 配色预设
- 未排期池拖拽入历；事件拖拽移动/调时长自动保存；逾期红边发光

### 排单列表 `/orders`
- 分页表（15/30/50/100 条）；阶段/来源/DDL/类别/搜索多维筛选（300ms 防抖）
- 批量操作按钮组（阶段/来源/收款/其他）；归档切换
- 每行显示剩余天数徽标（逾期红色/临期橙色/正常）

### 看板 `/orders/kanban`
- 阶段列拖拽（SortableJS）；hover 快捷 ◀/▶/✓
- 列头 sticky + 列统计（卡数+金额）；内容筛选；全量加载

### 画廊 `/gallery`
- 瀑布流 + 无限滚动懒加载；多条件筛选；Lightbox 查看
- 订单多图上传（粘贴/选择，≤10MB，自动生成预览+缩略图）

### 客户管理 `/customers`
- 列表按消费排序；标签 badge；total_spent/purchase_count 自动统计
- 详情页：基本信息 + 历史订单 + 作品画廊；平均时薪
- **VIP 客户**（Spec19）：VIP 徽标（列表行内 + 详情标题旁）+ 默认折扣 (%)；新建订单自动带出折扣快照

### 订单表单（3 种模式）

| 模式 | 入口 | 特点 |
|---|---|---|
| 居中模态 | 各处「新建」 | 快速创建 680px |
| 右侧抽屉 | 日历/甘特/列表点击 | 上下文编辑 480px + ColorPicker |
| 完整页 | 详情→编辑 | 平台/直接双财务模式实时预览 |

支持**订单模板**（`/templates` 完整页卡片式 CRUD 管理，新建订单弹窗可下拉预填/删除模板）与**阶段流程预设**（可拖拽排序+自动均分百分比）。截稿日期旁实时显示剩余天数。编辑态支持 Ctrl+S 快捷保存。五种表单（完整页/抽屉/模态新建/模态编辑/模板）均含**折扣 (%)** 输入：选客户自动带出其默认折扣（可手改/清空），实时预览「折后→费→实收」。

**分期收款**（Spec 26）：五种表单均含**收款方式**开关（默认「整单」，老习惯零差异；切「分期」显示提示）。分期单详情页提供**收款时间线**（按到账日排序：日期/金额/备注 + 应收净额/已到账/待收三数汇总 + 行内编辑器记一笔/改/删）；收齐自动结算置 `settled`（已结算）并走归档链；只进不退（删笔不回退状态，不一致显示警告条）；免收与分期互斥。

### 设置 `/settings`

- **主题设置**：11 色全局变量调色 + 自定义 CSS 主题导入/应用 + **深色主题引擎（Spec 32）**：按背景亮度自动判深、自动派生对比字色/深色变量/原生控件配色，全页面双主题对比度审计保障
- **着色模式**：5 种着色维度独立调色板 + 配色预设（保存/选用/更新/删除）
- **来源管理**：平台标记（`source` code，如 `mihuashi` 米画师）+ 费率% 配置（落 `choice_items` 表）；费率自动填充到订单表单
- **VIP 折扣预设**（Spec19）：预设折扣值标签增删（默认 95/90/88/80），挂到客户表单折扣输入 datalist
- **收款状态**：5 值（`deposit_paid`/`unpaid`/`settled`/`debt`/`waived`）锁定只读
- **稿件类别管理**：增删 + 合并功能（`commission_type` code，如 `cmt_001` 单人半身）
- **阶段流程管理**：流程预设编辑器（拖拽排序+进度均分）
- **时薪统计**：全局开关 + 单订单排除
- **外观**：字号 4 档 · 字体 3 种
- **快捷键**：自定义按键绑定
- **数据备份**：手动备份/恢复/删除 + **备份位置可配置**
- **日历订阅**（Spec20）：局域网 ICS 订阅（0.0.0.0:1097 第二监听 + token 鉴权），手机日历（iOS/Android）同步排期与截稿日；开关/URL 复制/令牌旋转；默认关闭
- **系统**：错误日志 · 更新检查 · 意见反馈入口

侧边栏「小工具」入口 → 市场页（搜索 + 分组过滤 + 最近使用横条）→ 工具详情页；内置工具注册进 `TOOL_REGISTRY`，第三方接入约定见 `.qoder/docs/tools-dev-guide.md`（只做约定不做加载器）。

## 关键业务口径（速查）

- **枚举存储（Spec 33）**：阶段/DDL/收款/来源/类别五类枚举**库里存英文 code、界面显中文**——如 `current_stage` 存 `pending`/`completed`，显示「待开始」/「完成」；改中文文案不动 code
- **收款状态 5 值锁定**：`deposit_paid` 已收定金 / `unpaid` 未收款 / `settled` 已结算 / `debt` 欠款 / `waived` 免收
- **自动归档**：阶段 ∈ {`completed` 完成, `cancelled` 退单} + 收款 ∈ {`settled` 已结算, `waived` 免收} → 归档并写 `completed_at`/`is_overdue` 快照（`PAID_STATUSES={'settled'}` 计收入 vs `ARCHIVE_PAID_STATUSES={'settled','waived'}` 判归档，二者刻意分离——免收可归档但不计收入）
- **财务**：`income = 定金+尾款`；**先折后费**（Spec19）：折扣非空 → `折后 = income × 折扣%`，平台来源 `platform_fee = 折后 × 快照费率%`；`actual_received = 折后 − fee`；折扣为订单级快照（客户改折扣不回溯存量订单）
- **统计金额**：工作口径一律 `actual_received` 净额；现金口径走收款事件流（Spec 26）——本期到账：整单按排期月 / 分期按到账日；待收金额 = 应收净额 − 已到账（分期）
- **复购**：查询时计算（同客户他单数，排除退单）
- **时薪**：`actual_received / work_hours`（加权口径）；全局开关 + 单订单排除

> 完整口径定义见 ARCHITECTURE.md §6.5 统计口径字典。

## 版本与数据兼容（v1.5.0）

**改了什么**：阶段 / DDL / 收款状态 / 来源 / 稿件类别五类枚举，**数据库里存英文 code，界面上仍显示中文**。例如 `orders.current_stage` 存 `pending`，界面显示「待开始」。好处是改中文文案不再影响存量数据，筛选、着色、统计也不会因为改名而失配。

**对用户可见的影响**：正常情况下**没有**。所有跨边界输出都经翻译层出中文 label，界面文字、下拉选项、图表标签、导出内容都还是中文。

**升级时会自动发生什么**（首次以 v1.5.0 启动）：

1. 先把现有 `orders.db` **重命名备份**为 `orders.pre-v1.5.0.db`——这个文件永不写入、须永久保留，是唯一的整体回退点
2. M0 预审计以严判据扫描歧义值，有歧义就不迁移
3. M0-M19 幂等迁移引擎把存量中文值一次性翻成 code，`PRAGMA user_version=33` 作为门闸（跑过就不再跑）
4. M19 是永久启动守卫，之后每次启动都会兜住任何残留中文值

**迁移失败不会锁死软件**：失败时降级为「兼容模式」启动（`settings` 表打 `enum_migration_failed` 标记），code 空间与未迁移中文空间可共存，软件继续可用。

**⚠️ 这是本项目唯一不可逆的数据动作**：迁移后不会自动把 code 还原成中文；要整体回退只能手动用 `orders.pre-v1.5.0.db`。恢复旧备份是安全的——兼容读会同时认 code 和旧中文值。

**已知限制（v1.5.0 收尾时登记，均为一般缺陷，不阻断使用）**：8 项已立卡 180-187，**执行仍需逐项批准**，故本版发布时未修：

| 编号 | 现象 | 卡 |
|---|---|---|
| G1 | 存量幽灵值 `'None'`（`orders.notes` 27 条 + `choice_items` 的 `cmt_016`），会作为图表第 6 扇区标签露出 | 180 |
| G2 | 备份目录累积 `-wal`/`-shm` 边车孤儿文件 | 181 |
| G3 | 损坏备份返回 `-1` 哨兵而非跳过，UI 把不可用备份呈现为可恢复 | 182 |
| G4 | 备份列表显示的是数据时间而非备份创建时间（`copy2` 保留了源库 mtime） | 183 |
| G5 | 「立即备份」/删除备份后「共 N 份备份」计数不刷新 | 184 |
| G6 | 归档确认弹窗文案与非终态触发场景不符 | 185 |
| G7 | 表单校验失败回显 Pydantic 原始英文错误（`app.py` 四处） | 186 |
| G8 | 未知路由 404 是 Werkzeug 默认英文页（缺 404 handler） | 187 |

**开发者专用页面**：统计实验室 `/stats-lab`（Spec 27，多维交叉统计 + 自然语言输入 + 预设持久化 + 口径速查表）受双闸控制——`data_dir()` 下存在 `.dev` 标记文件，或环境变量 `OIMIMO_DEV=1`；不在侧边栏导航中，普通用户看不到。
